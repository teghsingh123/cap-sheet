# Data pipeline

The data is built in two stages: a shared pipeline that every post reads
from, then one folder of scripts per post.

## 1. Shared pipeline

Run the scripts in `pipeline/` in numeric order, from inside `pipeline/`:

```
cd pipeline
py 00c_scrape_transactions.py   # Basketball-Reference season transaction pages -> scrape/transactions_html/
py 00d_parse_transactions.py    # scrape/transactions_html/*.html -> processed/transactions.csv
py 01_parse_salary_scale.py     # scrape/salary_scale_html/*.html -> processed/salary_min_scale.csv
py 02_parse_player_bios.py      # scrape/player_bio_html/*.html   -> processed/player_bios.csv
py 03_parse_draft_picks.py      # scrape/draft_html/*.html        -> processed/draft_picks.csv
py 04_build_vetmin_signings.py  # -> processed/new_contracts.csv, processed/vetmin_signings.csv, processed/kuminga_comps.csv
```

`04` also reads `source/salary_history.csv`, the one external dataset in
this pipeline (every player-season salary since 1991, not scraped by any
script here).

## 2. Per-post scripts

Each post has a folder under `posts/` named after its URL slug (the same
name as its folder in `web/src/posts/`). Its scripts read from `processed/`
and `source/`, and write the JSON that post loads to
`web/public/data/<slug>/`. Run them from inside the post's folder, after the
shared pipeline:

```
cd posts/kuminga-line
py 05_build_extra_charts.py     # -> web/public/data/kuminga-line/{all_signings,prove_it,young_fa}.json
py 06_build_min_scale_table.py  # -> web/public/data/kuminga-line/min_scale.json
py 07_check_known_cases.py      # checks those JSON files against hand-verified cases
```

`posts/vet-min-model/` is the next post (predicting who's out of the league
after a vet-min deal); see the README there.

## Folders

- `scrape/` -- raw HTML pulled from Basketball-Reference and RealGM. Input
  only; nothing here is generated by this pipeline.
- `source/` -- external data pulled from elsewhere (not scraped, not
  generated). Currently just `salary_history.csv`.
- `pipeline/` -- the shared scripts, in run order, plus `common.py`: the
  loaded data and the rules for "is this a new contract, for which team,
  signed when" that `04` and the per-post scripts all import, so every chart
  decides those the same way. `04` writes every new contract it finds to
  `processed/new_contracts.csv` (any salary), and the veteran-minimum subset
  to `processed/vetmin_signings.csv`.
- `processed/` -- intermediate CSVs the shared scripts write and every post
  can read. A file only one post needs belongs in that post's folder
  instead.
- `posts/<slug>/` -- the scripts (and any post-only intermediate files) for
  one post. `web/public/data/<slug>/*.json` is the final output the site
  loads.
- `archive/` -- superseded scripts and outputs that nothing in the current
  pipeline reads anymore, kept around instead of deleted in case any of it
  is useful later. Notably: an early first-pass YOS script
  (`derive_service_and_flag.py`), a draft-merge step later folded into
  `05_build_extra_charts.py` (`merge_draft_into_comps.py`), and several CSVs
  pulled early in the project that turned out not to be needed
  (`cap.csv`, `nba_salaries_master.csv`, etc.).
